# سجل القرارات المعمارية والهندسية (Architectural Decision Records - ADR)
## نظام إدارة مخازن وتجارة مواد البناء (ERP)

---

### ADR-001: اعتماد مبدأ ثبات التكلفة والسعر التاريخي (Historical Immutability)
* **الحالة:** معتمد (Approved).
* **السياق:** تجارة مواد البناء تتسم بتقلبات وتضخم سريع في أسعار الحديد والأسمنت. عند بيع شيكارة أسمنت بسعر 100 ج.م وكانت تكلفتها 80 ج.م، تم تحقيق ربح 20 ج.م. إذا ارتفع سعر السوق اليوم إلى 120 ج.م، يمنع أن تظهر الفاتورة القديمة بخسارة أو يعاد تقييم تكلفتها.
* **القرار:**
  * تخزين `unit_price_snapshot` و`historical_cogs_allocated` و`unit_entered_id` في كل سطر فاتورة لحظة الاعتماد.
  * عزل "تكلفة الاستبدال الحالية" (Current Replacement Cost) في مؤشر منفصل لأغراض التسعير المستقبلي للإدارة، دون المساس بالماضي.
* **الأثر:** حماية القوائم المالية وتقارير الأرباح التاريخية ومطابقة الإقرارات الضريبية لسنوات طويلة.

### ADR-002: دفتر حركات المخزون والمالية التراكمي (Append-Only Ledgers)
* **الحالة:** معتمد (Approved).
* **السياق:** في الأنظمة الرديئة يتم تحديث عمود `current_stock` أو `balance` بزيادة أو نقص مباشر، مما يؤدي عند حدوث أخطاء أو انقطاع اتصال إلى فقدان أصل الحركة واستحالة تفسير الفروق الجردية.
* **القرار:**
  * استخدام جدولي `stock_movements` و`cash_movements` كدفاتر أستاذ إلكترونية لا تقبل التعديل أو الحذف (`Append-Only`).
  * رصيد أي مخزن أو خزينة هو ناتج تجميع الحركات السابقة المعتمدة.
  * لا يوجد حذف لمستند معتمد؛ التصحيح يتم دائماً بمستند عكسي معتمد (`reversal_document` / `credit_note`) مع تسجيل كامل في `audit_logs`.
* **الأثر:** إمكانية إعادة بناء ومطابقة أي رصيد في أي تاريخ سابق بنسبة دقة 100%.

### ADR-003: المعاملات الذرية للعمليات متعددة الخطوات (Atomic DB Transactions via RPC)
* **الحالة:** معتمد (Approved).
* **السياق:** اعتماد الفاتورة يتطلب عدة خطوات متتالية: التحقق من الرصيد المتاح، خصم المخزون، استنزاف طبقات التكلفة، قيد مديونية العميل، وإنشاء سند القبض إن وجد. إذا تمت هذه العمليات عبر طلبات HTTP منفصلة من المتصفح، فإن فشل أي طلب يترك النظام في حالة غير متسقة (Inconsistent State).
* **القرار:**
  * تنفيذ جميع العمليات المتشابكة داخل دوال مخزنة (PostgreSQL Stored Procedures / RPC Functions) داخل Transaction ذرية واحدة تضمن الـ ACID (إما أن تنجح جميع العمليات أو يتم التراجع عنها بالكامل).
* **الأثر:** منع ظهور فواتير معتمدة بلا خصم مخزني أو العكس، وحماية النظام من تلاعب المتصفح.

### ADR-004: محرك تكلفة مرن يدعم FIFO كأولوية أمان (Configurable Costing Engine)
* **الحالة:** معتمد (Approved).
* **السياق:** لم يتم حسم سياسة التكلفة نهائياً من قبل محاسب المنشأة (FIFO vs المتوسط المرجح).
* **القرار:**
  * تصميم جداول طبقات التكلفة (`inventory_cost_layers`) وتخصيص التكلفة (`cost_allocations`) بحيث تدعم نمط FIFO افتراضياً (لأنه الأكثر تدقيقاً وتوثيقاً لحركات الشراء والتوريد)، مع دعم المتوسط المرجح عبر محرك وسيط قابل للتبديل لكل منشأة/مخزن دون الحاجة لإعادة كتابة قاعدة البيانات لاحقاً.
* **الأثر:** جاهزية النظام لأي قرار يعتمده المحاسب دون تعطيل التطوير.

---

### ADR-005: منع المخزون السالب كإعداد أمان افتراضي (Default Negative Stock Prevention)
* **الحالة:** معتمد (Approved).
* **السياق:** بيع مواد بناء غير موجودة دفترياً بالسالب ينتج عنه غياب تكلفة شراء مقابلة لإغلاق الـ COGS.
* **القرار:**
  * فرض فحص الرصيد المتاح على مستوى قاعدة البيانات ومنع الخصم إذا كان الرصيد غير كافٍ.
  * في حال أراد المحاسب استثناءات للمديرين، يتم تفعيلها عبر Feature Flag مقيد بصلاحيات تدقيق صلبة.
* **الأثر:** ثبات وسلامة حسابات تكلفة البضاعة المباعة والربحية.

### ADR-006: معالج Excel الآمن (Secure Multi-Step Excel Engine)
* **الحالة:** معتمد (Approved).
* **السياق:** يعتمد تجار مواد البناء على ملفات Excel بشكل يومي، واستيراد ملف مباشرة قد يدمر قاعدة البيانات أو يكرر العملاء والأصناف أو يسبب أخطاء صامتة.
* **القرار:**
  * اعتماد دورة استيراد خماسية: الرفع ← مطابقة الأعمدة (Mapping) ← التحقق وكشف التكرار ← محاكاة تجريبية (Dry Run) دون كتابة ← تأكيد صريح واستيراد ذري مع تقرير أخطاء قابل للتنزيل.
  * حماية التصدير من Formula Injection.
* **الأثر:** تجربة Excel قوية مع حماية مطلقة للبيانات التشغيلية.
